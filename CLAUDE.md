# Kit PvP — BACKEND (game server; started as the Bowling Roll server)

Frontend (3D client) lives at `../Bowling-roll`. Colyseus + Mongo, ported from `C:\ThreeJS\Kayak-and-surf\Kayak-and-surf -backend`.

- **Kit PvP room `kitpvp`** (`src/rooms/KitRoom.ts`, schema `KitState.ts`, bounds `src/kitRelay.ts`, identity `src/auth.ts`, constants `KIT` + `ROOM_MAX_CLIENTS` = 20, tests `test/Kit.test.ts`): what the Kit PvP client (`../Bowling-roll/src/net.js`) joins with `joinOrCreate("kitpvp", { token, kit, pose })`. Roster `KitPlayer`: name (Bloxity display name verified with `POST {BLOXITY_API_URL}/v1/auth/game-token/verify` { gameSlug }, else "Guest 1234"), signedIn, seed (skin), zone (lobby/drop/arena/dead), kit, pose (x y z yaw pitch speed vx vy vz), hp, flags (client FLAG bits), swing (counter), item, kills, streak, joinedAt; `host` = sessionId that simulates the arena bots (the earliest player in the arena, kept while it stays there; "" when nobody fights). Combat is client-authoritative and relayed: `hit` { to, amount, opts, bot? } -> the victim's client (both in the arena, within `KIT.hitRange`, amount <= `maxHit`, opts whitelisted, `hitsPerSecond`; `bot` only from the host), `botHit` { bot, ... } -> the host, `act` { to | bot, type: status/ignite/push/teleport } -> that player / the host, `fx` (cosmetic replays, size + rate capped) and `bots` (the host's snapshots) broadcast, `died` / `botDied` -> `feed` to everyone else + `kill` { victim, streak } to the killer (who pays itself), `summon` { a: { count, hp, life, kind: zombie | wolf } } -> the host (Necromancer zombies, the Wolf Tamer's wolf). Reconnect window `KIT.reconnectSeconds`.
- **Kit PvP saves + leaderboards** (`src/kitStore.ts`, Mongo collection `kitpvp` from `db.ts` `getKitPlayers()`, indexes on kills/gold/playtime/rating): a verified player's save is loaded on join -> `progress` { save, duelsWon, duelsLost } (or `noProgress` { reason: new | guest | error }; error = never write). Client `save` (whole state.js snapshot, debounced) is bounded by `sanitizeKitSave` (numbers clamped to `KIT.save`, id lists, hotbar of 9, settings flags, `mastery` { kitId: kills }, `borrow` { id, kind: trial | rent, paid, used } or null (a kit borrowed for one arena life), `trialDay`; the equipped kit/look must be owned; never `rating`/`duelsWon`/`duelsLost`) and written at most every `KIT.saveEveryMs` (`flushSaves`), only after the load answered; guests' saves only feed the live boards. `leaderboard` { boards: { kills, playtime, gold, rating: [{ name, level, value }] } } on join, every `KIT.boardEveryMs` and after a ranked result: the top saved players (`savedTops`, cached) merged with this room's players (live saves; ranked only once rated away from the start).
- **Duels** (`src/duels.ts` DuelBook + KitRoom): `duelQueue` { mode: casual | ranked } (roster `queued`), `duelCancel`; two in the same mode's queue get a free platform slot (`KIT.duel.slots`, the client's DUEL.slots) -> `duelStart` { id, slot, mode, side, opponent, opponentId, opponentRating, rating } (roster `duel` = id; hits/acts are then relayed only between the two, `together()`), then `duelRound` { id, round, score, countdownMs } (deaths during the countdown don't count), `duelDied` -> `duelScore` { id, score, roundWinner } and after `betweenMs` the next round, until `KIT.duel.wins` -> `duelEnd` { id, won, score, forfeit, mode, delta, rating }. Ranked: Elo (`eloDelta`, K = `KIT.duel.k`) on the roster `rating`, saved for verified players (`saveRating`, + duelsWon/duelsLost). `duelLeave` or leaving the room = forfeit. Tests `test/KitDuels.test.ts` (fast `countdownMs` in the test).
- The `world` room below is the old Bowling Roll room this repo was ported from (still registered, unused by Kit PvP).
- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- The client keeps NO progress in the browser: this server's Mongo doc is the player's only save. A guest's (or a serverless session's) progress lasts the page only.
- Messages client -> server: `saveProgress` (the whole snapshot, debounced client-side), `identify` (`{ userId, username, pfp }` after a sign-in/out mid-session), `race` (`{ racing, distance }`, a few times a second while racing; distance clamped 0..`DISTANCE_MAX`, 0 when not racing). Server -> client (private): `progress` (the saved doc, sanitized), `noProgress` (new account, guest, or no database: the client keeps its fresh state and saves it), `serverError` (the save could not be read: saving stays off so it is never overwritten). Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp` (Bloxity profile picture URL, http(s) only, max `PFP_MAX_LEN`, "" = none), `racing`, `distance` (studs this race): every client draws the other racers' heads on its distance bar and 1st/2nd/3rd podium from it (`test/Roster.test.ts`).
- Saved progress shape (`PlayerDoc`, client `src/net.js` `progress()` + each window's `snapshot()`): `trophies` (Wins), `gems`, `energy` (lightning), `rebirths`, `autoRebirth`, `bestDistance` (studs, `$max` so it never drops), `playtime`, owned/equipped pairs `boats`/`boat`, `engines`/`engine`, `partners`/`partner`, `trails`/`trail` ("" = none equipped; the equipped id must be owned), `pets[] { kind, tier, equipped, locked }` (equipped capped at `petSlots`), `petSlots`, `petStorage`, `eggsSeen[]` (pet kinds ever hatched), Online Gifts `giftTime` (s), `giftsClaimed[]` (GIFTS.list indexes), `potions { id: n }`, `lastSeen`, `world` (the client WORLDS id the player was in, "" = the start world) and `worldsUnlocked[]` (worlds whose portal requirement was met once).
- Spin wheel (`src/spin.ts`, constants `SPIN_*`): server-authoritative, unlike the rest of the save. Each session's `{ spins, nextAt }` lives in `spinStates` (read from the doc's `spins`/`spinAt` on load; a new player gets `SPIN_START`), one free spin accrues every `SPIN_EVERY_MS` of real time up to `SPIN_CAP` (the clock waits while capped). After the load the server sends `spins` { spins, nextAt, serverTime }; `spin` spends one, rolls a `SPIN_WEDGES` id by weight and answers `spinResult` { ok, id, spins, nextAt, serverTime } (or { ok: false, reason: "loading" | "none" }), then writes `spins`/`spinAt` itself. `saveProgress` never carries them (not in sanitize.ts). Guests / no-DB sessions keep theirs in memory for the connection. The client grants the prize (its `SPIN.wedges` by id).
- Daily Reward (`src/daily.ts`, `DAILY_DAYS` = the client's `DAILY.days.length`): server-authoritative on the server's UTC clock. Doc fields `dailyDay` (days unlocked this cycle), `dailyLast` (UTC day index of the last unlock), `dailyClaimed[]` (0-based days), written only by the server (`saveDaily`), never by `saveProgress`. On load (`loadProgress`) the state goes into `dailies` per session, today unlocks (`rollDaily`: +1 day per new UTC day, capped; all claimed -> back to day 1) and the client gets `daily` { unlocked, claimed, nextAt, serverTime }. `claimDaily` { day } answers `dailyResult` { ok, day, reason?: "loading" | "locked" | "save", ...view } (ok only once stored); `dailyRefresh` re-rolls after midnight and answers `daily`. Guests / no-DB sessions keep theirs in memory for the connection. Tests: `test/Daily.test.ts` (shared fake Mongo in `test/fakePlayers.ts`).
- Leaderboards (`src/leaderboard.ts`, `test/Leaderboard.test.ts`): the client plaza's four boards. Top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`rebirths`, `trophies` = Wins, `energy` = Power, `playtime`), read with find/sort/limit into one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; each player's own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). Server -> client `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } }, sent after each load and to everyone every `LEADERBOARD_EVERY_MS` (room clock). `connectDb` creates a descending index per stat. The test fake supports just that find/countDocuments shape.
- Presence (`src/presence.ts`, `test/Presence.test.ts`): what the others draw in the world, relayed through the roster as sent, only bounded. Roster fields `x`/`y`/`z` (feet, TRACK coordinates: z minus the sender's race scroll), `yaw` (wrapped to -PI..PI), `speed` (m/s), `boat`/`engine`/`trail`/`partner` (catalog ids matching `ID_PATTERN`, "" = none), `pets` ("kind:tier,...", at most `PRESENCE_PETS_MAX`), `avatar` (Bloxity look JSON, at most `AVATAR_MAX_LEN`, never parsed). Messages `pose` { x, y, z, yaw, speed } (~10/s, bounds `POSE_BOUNDS`), `loadout` { boat, engine, trail, partner, pets: [{ kind, tier }], world } (roster `world`: clients only draw players in their own world), `setAvatar` { avatar }; the join options may carry `pose`, `loadout` and `avatar` too.
- `src/constants.ts` bounds must cover the client's `src/config.js` (catalog ids match `ID_PATTERN`, incl. engine `ladder-N`; currency up to ~3.6e28). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (keep it 2-100 for party play; no `seatCap`: the matchmaker sizes pods). Needs repo var/secret `LEGION_GAME_ID` (= `18-kit-pvp`, also the client's GAME_SLUG) and secret `LEGION_DEPLOY_TOKEN`.
- **Boxity integrations** (`src/boxity/`, `src/legion-room-reporter.ts`, `test/Boxity.test.ts`). Everything that reports to Boxity is a no-op without the hosting env (`BLOXITY_REPORT_TOKEN` + `BLOXITY_GAME_ID`; `BLOXITY_API_URL` falls back to prod, `BLOXITY_GAME_SLUG` to `kit-pvp`, `MATCHMAKER_REPORT_URL` for the room directory), never throws into the game and logs the API's answer. Started from `src/index.ts` after `listen()` (`installRoomReporter`, `installBoxityReporters`; SIGTERM/SIGINT drain).
  - **Server-owned counters** (`mirror.ts`): per signed-in user `pvpKills`, `bestStreak`, `duelsWon`, `duelsLost`, `rating` loaded from the save doc on join (`KitDoc.pvpKills` / `pvpBestStreak` are server-only like the rating; `sanitizeKitSave` drops them) and updated only by events the server saw: `KitRoom.countPvpKill` (a player victim, never a bot; killer verified and in the arena; `KillGate` = one counted kill per killer per `KIT.killGapMs`; `savePvpKill` $inc/$max) and the ranked duel result (`recordDuel`; only ranked duels are persisted, so only they count). No mirror when the save could not be read (never report zeros). Stats, boards and badges read ONLY from here.
  - **Stats** (`stats.ts`): every 60 s + drain, `POST {api}/v1/games/{id}/stats`; keys `pvp_kills`, `best_streak`, `duels_won`, `duels_lost`, `rating`; ids `legion_<id>`, batches of 200, values validated (finite, 0..1e9).
  - **Leaderboards** (`boards.ts`, `leaderboards.ts`): `BOARDS` = kills (sum, weekly), streak (best, weekly), duels (sum), rating (best). **The client passes the identical array to `Legion.SDK.leaderboard.define()`**; keep them in step. Every 15 s, after a ranked duel and on drain, `POST {api}/v1/leaderboards/hosted/{id}/report`: sum boards send the gain since the last landed batch (kept on failure), streak = this session's best, rating once away from the start rating.
  - **Badges** (`badges.ts` pure rules, `badgeClient.ts`): 11 emoji badges declared at start (retry 30 s), `owned` on each signed-in join, `award` on kills / ranked duels (set first, removed on failure; a 403 turns badges off for the process).
  - **Room directory**: `legion-room-reporter.ts` (verbatim from the docs); `ROOM_MAX_CLIENTS` stays 20 (2-100) for party play / Open Rooms.
  - **Messages**: roster `KitPlayer.uid` = verified Bloxity id ("" guest; chat bubbles match `m.userId`). Client -> server `emote { id }` (24 lower-case hex, 1/s per client, opaque) -> others get `emote { from, id }`. Client -> server `adReward { placement: "bonus-gold", token }` (verified signed-in only, `KIT.ad` 60 s cooldown, 20 per session; token checked with `POST {api}/v1/ads/reward/verify`) -> that client gets `adRewardResult { ok, placement, gold, reason? }` with `gold` = `AD_REWARD_GOLD` (150) when ok; the client grants the Gold (saves are client-authoritative). Rewarded ads pay Gold only, never Gems.
- **Bloxity look relay** (`kitRelay.ts applyAvatar`, `KIT.avatarsPerSecond` = 2, `AVATAR_MAX_LEN`): roster `avatar` (string, "" = stock rig) is the sender's look JSON (`{ e, p }`), set from the join option `avatar` and the `setAvatar` { avatar } message; the server never parses it (the receiving clients validate it), it only rejects non-strings / over-long strings and rate-limits. Test in `test/Kit.test.ts`.
